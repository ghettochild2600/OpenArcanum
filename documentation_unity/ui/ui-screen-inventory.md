## UI-E.1 inventory/equipment foundation closure

`arcanum-ce/src/ui/inven_ui.c` is the controlling source evidence for ordinary Inventory. It creates the 800 x 400
middle window, blits ID 223 at x=0 and ID 221 at x=358, maps the 10 x 12 inventory grid from x=368/y=8, and defines
the nine equipment rectangles and empty-slot ART identities recorded above. The ordinary path does not establish ID
341 as a composition layer, so that earlier speculation is rejected rather than promoted to runtime behavior.

Production `RetailInventoryEquipmentView` is a disposable projection owned by the existing presenter. It reads
retained item identity, inventory ART ID, footprint, grid location, stack quantity, and worn location from
`GameUiController`; selection, equip/unequip, and quick-slot assignment submit existing controller commands. Retail
item ART is decoded lazily through the mounted VFS and never copied into the repository. Enhanced interface panels use
the existing exact-4x UI-A resolver and per-asset Original fallback. Distinct paper-doll composite ART cannot be
derived from the retained inventory ART ID and therefore remains explicitly deferred instead of being guessed.

Physical Play Mode used the existing Editor, production scene, and a fresh authentic crash-site character. The source
window remained aligned and unclipped at 800 x 600, 1024 x 768, 1920 x 1080, 2560 x 1440, and 3840 x 2160. Authentic
starting items rendered in the retained grid/slots; selection, quick-slot binding, equip, and unequip each occurred
once through existing authority. The HUD stayed present, one inventory view/presenter/controller/EventSystem remained,
and Original → Enhanced exact-4x panels → Original rebuilt presentation without changing item or screen state.

## Shared controls and reuse rules

Buttons, pressed/hover/disabled states, arrows, checkbox/radio controls, scrollbars, cursors, portrait/item frames,
confirmation windows, text colors/fonts, and invalid feedback belong to a common UI presentation package. The same
source identity may be used by multiple screens; screen directories must not duplicate its replacement pixels.

Original and Enhanced modes always share the same logical rectangle, pivot, hit rectangle, modal ordering, focus,
keyboard route, and controller command. A mode switch may rebuild presentation but cannot mutate screen state or
gameplay. Where no authoritative controller exists (notably Sleep/Fate and parts of Local Map), the screen remains
unavailable or read-only rather than silently adding gameplay.

## Character Creation usability requirement

At 1920 x 1080, 2560 x 1440, and 3840 x 2160, the complete primary 800 x 400 editor fits without horizontal
scrolling. Initial identity selection and fixed subpanels remain visible at the same logical geometry. Only source-long
lists may use a vertical scroller, with focus and keyboard behavior matching the original intent.
